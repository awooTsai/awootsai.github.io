# 專員體質健檢核心規則

> 此 Skill 是給 **awoo 內部 SEO 專員** 的執行工具。
> 與 `ada-geo-site-audit`（業務提案版）互補但定位完全不同。

---

## 1. 與業務版的根本差異

| 維度 | 業務版（site-audit） | 專員版（tech-audit，本 Skill） |
|------|-------------------|---------------------------|
| 對象 | 客戶 | 內部專員 |
| 目的 | 讓客戶感受問題 | 讓專員快速執行 |
| 口吻 | 客觀觀察、不批判 | 直接、技術導向 |
| 內容深度 | 三大痛點為主 | 全項展開 |
| 術語 | 白話括號（H1→頁面主標題） | 業界術語直用（H1、canonical） |
| 範例 URL | 3 個代表 | 全部清單 |
| 區分事實 vs 推論 | 不需要 | **必須區分** |
| 對外呈現 | 是 | **不對客戶呈現** |

---

## 2. 區分「事實」vs「推論」

### 標記規則

每個觀察必須標示：
- 🔵 **爬蟲事實**：harvester 直接取得的客觀資料
- 🟡 **AI 推論**：基於資料做出的判斷

### 範例

#### 🔵 爬蟲事實（不容質疑）
- 「網站總頁數 247 頁」（_rag_summary.json 直接讀取）
- 「Title 多樣性 85%」（直接計算）
- 「H1 缺失頁面 23 頁」（爬蟲偵測）
- 「FAQ Schema 數量 0」（爬蟲偵測）

#### 🟡 AI 推論（需專員驗證）
- 「此頁疑似為測試頁」（基於 URL 模式 + 內容判斷）
- 「Schema 可能未完整實作」（基於 Schema 數量推論）
- 「此業態傾向為 [XX]」（基於內容主題判斷）
- 「以下 URL 疑似為廢棄商品頁」（基於頁面內容判斷）

讓專員一眼分辨哪些是不容質疑的事實、哪些需要進一步驗證。

---

## 3. 報告結構

### 標準四段式
```
1. 爬蟲事實總覽
   - 頁數、Schema 統計、缺失統計
   - 表格化呈現

2. 各檢查項目展開
   - URL 一致性
   - H 標籤結構
   - Schema / JSON-LD
   - Canonical / noindex
   - 文章新鮮度

3. AI 推論需驗證項目
   - 每項標明推論依據
   - 提供原始資料連結（讓專員可深入查看）

4. 與業務版的對照（如有）
   - 業務版聲明的觀察
   - 專員版的實際資料對照
   - 標記任何矛盾點
```

---

## 4. 提供原始資料展開

業務版只列 3 個範例，專員版**必須列出全部**：

### 範例：缺 H1 的頁面
業務版：
> 「您的網站約 23 頁缺少 H1，例如：
> - example.com/page-1
> - example.com/page-2
> - example.com/page-3」

專員版：
```html
<details>
  <summary>缺 H1 的頁面（共 23 個）</summary>
  <ol>
    <li>example.com/page-1</li>
    <li>example.com/page-2</li>
    ...（全部列出）
    <li>example.com/page-23</li>
  </ol>
</details>
```

讓專員可以複製貼上去逐項檢查。

---

## 5. 內部術語可直接使用

業務版禁用的術語，專員版可直接用：
- ✅ harvester、Content Harvester
- ✅ RAG chunks、metadata
- ✅ pages.zip、_rag_summary.json
- ✅ 任何 SEO 業界縮寫不需要白話括號

但要避免：
- ❌ 客戶實名（除非在內部討論時）
- ❌ 報價金額或商業敏感資訊

---

## 6. 與業務版報告的對照

如果使用者已先用 ada-geo-site-audit 產出業務版健檢，再用本 Skill 產專員版：

### 必做動作
1. 讀取業務版報告（如有提供 HTML 檔）
2. 對每個業務版的觀察，找出原始資料佐證
3. 標記任何「業務版說有問題，但原始資料看不出問題」的矛盾點
4. 標記任何「原始資料有問題，但業務版未提及」的遺漏

### 矛盾點處理
- 在報告中明確標示矛盾
- 提供原始資料連結
- 不直接修改業務版內容（這是阿達決定的事）

---

## 7. 輸出規格

- 檔名：`{品牌英文 slug}_tech_audit_{YYYY-MM-DD}.html`
- ASCII only
- 輸出到 `/mnt/user-data/outputs/`

---

## 8. 視覺風格

### 與業務版的差異
- 表格化呈現多
- 資訊密度高
- 顏色使用較少（避免分散注意）
- 字體可略小（但仍 ≥ 15px）

### 完全沿用 _shared/visual-system.md
- 字體系統相同
- 色彩變數相同
- 但區塊組合方式不同（表格 + 展開列表為主）

---

## 9. footer 微調

專員版 footer 應微調為：

```html
<div class="footer-p1">本技術盤點透過 awoo 阿物科技 近 20 年資料庫與 AI 運算生成（掃描日期 SCAN_DATE）</div>
<div class="footer-p2">⚠️ 此報告僅供 awoo 內部專員執行使用，不對客戶呈現</div>
```

第二段強調「不對客戶呈現」是專員版的重要識別。

---

## 10. 不做的事

- ❌ 不寫 CTA（這是給專員看的執行清單，不是業務文件）
- ❌ 不寫品牌包裝（不需要 strength banner）
- ❌ 不寫 Hero 大數字渲染（直接表格呈現）
- ❌ 不做 Glossary（專員看得懂）
